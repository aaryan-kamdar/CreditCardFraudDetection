# Credit Card Fraud Detection

A machine learning pipeline that flags fraudulent credit card transactions in near real-time, built to handle extreme class imbalance (<1% fraud) without drowning a fraud team in false alarms.

## Problem Statement

A bank needs to catch fraudulent transactions as they happen, but fraud makes up less than 1% of all transactions. A naive model that predicts "not fraud" every time would be 99%+ accurate and completely useless. This project compares multiple approaches to extreme imbalance and selects the one that minimizes real-world cost — not just the one with the best accuracy.

## Results Summary

Five approaches were compared: class-weighted Logistic Regression, three SMOTE oversampling strategies, and Isolation Forest (unsupervised anomaly detection).

Model	Precision	Recall	PR-AUC
SMOTE 50%	0.055	0.918	0.719
SMOTE Full Balance	0.054	0.918	0.719
SMOTE 10%	0.055	0.918	0.719
Class-Weighted LR	0.055	0.908	0.713
Isolation Forest	0.269	0.296	0.166

**PR-AUC (Precision-Recall AUC) was used as the primary metric**, not ROC-AUC or accuracy — at under 1% positive class, ROC-AUC can look deceptively good even for a weak model, since it's dominated by how well the model ranks the overwhelming majority class.

The winning model's decision threshold was tuned using an explicit cost function (estimated cost of a missed fraud case vs. a false alarm), rather than a default 0.5 cutoff or an arbitrary recall target. Full reasoning in [`report.md`](report.md).

## How to Reproduce

### 1. Clone the repo and set up the environment
```bash
git clone https://github.com/<your-username>/credit-card-fraud-detection.git
cd credit-card-fraud-detection
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

### 2. Get the dataset
Download the [Credit Card Fraud Detection dataset](https://www.kaggle.com/datasets/mlg-ulb/creditcardfraud) from Kaggle and place it in `data/` as `creditcard.csv`. Note: this file is ~150MB and is not committed to the repo (see `.gitignore`).

### 3. Train and compare all models
```bash
cd src
python train_fraud.py
```
This cleans the data, trains and compares all 5 approaches, automatically selects the best one by PR-AUC, tunes a cost-sensitive decision threshold, and saves everything to `models/` and `reports/`.

## Methodology

1. **Data cleaning** — log-transformed the heavily skewed `Amount` column; converted `Time` (raw seconds elapsed) into `Hour` of day, a cyclical and more interpretable feature
2. **Split first** — stratified train/test split before any resampling, to prevent synthetic or class-balance information from leaking into the test set
3. **Approach A: Class weighting** — `class_weight="balanced"` on Logistic Regression, the simplest baseline
4. **Approach B: SMOTE oversampling** — compared three sampling ratios (10%, 50%, full 1:1 balance) using an `imblearn.pipeline.Pipeline`, which ensures resampling only ever touches training data, never the test set
5. **Approach C: Isolation Forest** — an unsupervised anomaly detection model, trained without labels, that flags transactions unlike the "normal" pattern it learned. Included because it doesn't rely on having many labeled fraud examples to work, unlike the supervised approaches
6. **Evaluation** — Precision, Recall, F1, ROC-AUC, and **PR-AUC** (the primary metric, given the extreme imbalance)
7. **Cost-sensitive threshold tuning** — rather than a default 0.5 cutoff, searched all possible thresholds to find the one minimizing total estimated cost, using assumed costs for a missed fraud case vs. a false alarm
